# Viber Astana Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver the September 30 Astana event from QR check-in through teams, challenges, project launch, public voting, and judges' published top three.

**Architecture:** Add an event-specific module to the existing app, with separate guest identities and stable event-team IDs. Reuse the current event catalog, admin authentication, arena, and wheel through a small adapter. Persist guest submissions and votes in dedicated tables so legacy account/team routes cannot change them accidentally.

**Tech Stack:** Existing React 18, TypeScript, Express, Drizzle/Neon PostgreSQL, TanStack Query, Tailwind, Zod, and qrcode; Node test runner via tsx.

**Spec:** `docs/superpowers/specs/2026-09-30-astana-proposal.md` (approved by the user).

## Global Constraints

- September 30, 2026; Nur Alem Pavilion, Network School floor (5th floor); do not invent a start time.
- 60 minutes to build, 60 seconds to pitch, founder-life challenges every 10 minutes.
- Name and email entry; no payment, Discord, NS membership, password, or email-verification prerequisite.
- Follow link is https://x.com/viberventures; self-confirmation is not API verification.
- Pairs by default; one trio for an odd roster; late arrivals do not force a full reshuffle.
- One project per team, with hosted app URL, thumbnail URL, and optional social-post URL.
- Audience ratings and judges' placements are separate.
- Emails, guest tokens, and draft winners never appear in public responses.
- Preserve previous events. Do not use drizzle-kit push or run tests against the shared live database.
- Keep existing typography and arena styling; no new design system or broad refactor.
- Poll no faster than 15 seconds and suspend background polling.

## Review Focus

1. A participant scans in an in-app browser, then loses that session: organizer recovery must issue a new token and revoke the old one without authenticating by email alone (Task 1).
2. Two operators assign teams, transfer members, or save winners simultaneously: transactions and revisions must reject stale writes (Tasks 2 and 4).
3. Most voters share venue Wi-Fi: per-visitor limits must permit the room to vote, with only a generous IP abuse ceiling (Task 4).
4. A founder dispute affects only one or two teams: do not require three selections or open an impossible rotation dialog (Task 3).
5. A participant submits while being transferred, or two teammates save at once: authorization and revision checks happen within the same transaction as the write (Task 4).

## Shared Contracts

Use UUID strings for all new guest/team/project IDs; existing event IDs remain numbers. Names below are the contract between tasks.

```ts
export const ASTANA_SLUG = 'viber-astana';
export type Guest = { id: string; name: string; teamId: string | null };
export type EventTeam = { id: string; name: string; members: Guest[] };
export type ProjectInput = {
  title: string; description: string; appUrl: string;
  thumbnailUrl: string; socialUrl: string | null; revision: number;
};
export type Project = ProjectInput & {
  id: string; teamId: string; teamName: string;
  averageRating: number; ratingCount: number;
};
export type Me = { guest: Guest | null; team: EventTeam | null; project: Project | null };
export type Winners = { published: boolean; projects: Project[] };
export type AdminState = {
  eventId: number; rosterRevision: number; judgingRevision: number;
  guests: (Guest & { email: string })[]; teams: EventTeam[];
  projects: Project[]; draftProjectIds: string[]; publishedProjectIds: string[];
};
```

`createAstanaRouter({store, requireAdmin, broadcast})` returns an Express Router. Mount under `/api/astana` after cookieParser. `store` is an `AstanaStore` backed by injected Drizzle database connection; production composition imports `db`, HTTP tests inject a fake, database tests inject a disposable PostgreSQL connection. Store operations throw `AstanaError(status, message)`; router catches it and returns `{message}` without raw SQL details.

Endpoint contract:

| Method/path under /api/astana | Input | Output/access |
|---|---|---|
| GET /event | none | public event metadata |
| POST /join | name,email,followConfirmed | Me; sets guest cookie |
| GET /me | guest cookie | Me; anonymous is guest:null |
| GET /projects | none | Project[] |
| PUT /project | ProjectInput | current team's Project; guest only |
| POST /visitor | none | 204; sets visitor cookie idempotently |
| PUT /projects/:id/rating | rating integer 1–5 | Project; visitor cookie |
| GET /winners | none | Winners; published values only |
| GET /admin | none | AdminState; admin only |
| POST /admin/assign | rosterRevision | AdminState |
| POST /admin/move | guestId,teamId,rosterRevision | AdminState |
| POST /admin/rotate | guestIds:string[],rosterRevision | AdminState |
| POST /admin/recover/:guestId | none | single-use recovery URL |
| POST /recover | recovery token | Me; new session, revoke prior sessions |
| PUT /admin/winners | projectIds:string[],judgingRevision | AdminState draft |
| POST /admin/publish | judgingRevision | Winners |
